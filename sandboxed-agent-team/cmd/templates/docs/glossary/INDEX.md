# Glossary — Index

The project's canonical vocabulary, split into two files by audience.
Both files use inline Markdown anchors so other docs can link directly
to individual terms.

When a technical term corresponds to or intentionally diverges from a
business term, the technical entry includes a "See also:" link to the
business term. This makes the relationship explicit without requiring
both files to stay in sync.

| File | Owner | Purpose |
|------|-------|---------|
| [business.md](business.md) | Analyst — commits on requirement branches | Business and domain vocabulary: ambiguous, project-specific, or user-facing terms. Implementation-agnostic. |
| [technical.md](technical.md) | Architect — commits on `pattern/<slug>` branches | Technical and implementation vocabulary: concrete class names, architectural concepts, stack-specific terms. |
