# Patterns — Index

Application-agnostic conventions, architecture patterns, recipes, and implementation
guidelines for **Vaadin 24+ with Spring Boot 3+** and Spring Data JPA. Version-
sensitive patterns carry inline "Vaadin ≥X / <X" notes; see [`README.md`](README.md)
→ "Version Compatibility" for the summary matrix. Zero project-specific content.

### Services

| Path                                                                                        | Description                                                                                                                                                                                            |
|---------------------------------------------------------------------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| [structure/services/service-naming.md](structure/services/service-naming.md)               | When naming service classes, use `{Domain}Service` for interfaces and `{Technology}{Domain}Service` for implementations so the backing technology is apparent from the name                             |
| [structure/services/service-method-naming.md](structure/services/service-method-naming.md) | When naming service methods, use `listAll*()`, `findByKey()`, `create*()`, `update*()`, `deactivate*()` so callers infer query vs. mutation from the name                                               |
| [structure/services/service-interface.md](structure/services/service-interface.md)         | When writing service interfaces, operate exclusively on UI models and group queries before mutations so the contract is decoupled from persistence                                                       |
| [structure/services/service-transactional.md](structure/services/service-transactional.md) | When annotating service implementations, apply `@Transactional(readOnly = true)` on queries and `@Transactional` on mutations so Hibernate skips dirty checking on reads                               |
| [structure/services/service-update.md](structure/services/service-update.md)               | When implementing an update, load the managed entity and apply changes via MapStruct `@MappingTarget` so dirty checking flushes without a redundant `save()`                                            |
| [structure/services/service-insert.md](structure/services/service-insert.md)               | When implementing an insert, create a new entity instance and call `repository.save()` only on the transient (null-key) entity                                                                          |
| [structure/services/service-grid-loading.md](structure/services/service-grid-loading.md)   | When loading grid data, return a full `List<T>` from the service and wire it to `CachingDataProvider` in the view so the Grid shows its loading indicator while sorting and filtering run in-memory   |
| [structure/services/service-caching.md](structure/services/service-caching.md)             | When caching frequently read data, apply Spring `@Cacheable` at the service layer and `@CacheEvict` on mutations so cache invalidation is co-located with the data it guards                           |
| [structure/services/service-errors.md](structure/services/service-errors.md)               | When a service encounters a predictable failure, throw `EntityNotFoundException` or `ValidationException` so views control error presentation and raw database errors never reach the user             |
| [structure/services/service-mapper.md](structure/services/service-mapper.md)               | When mapping between JPA projections, UI models, and entities, use MapStruct with `@MappingTarget` for updates so unrelated entity fields are preserved                                                |
| [structure/services/service-osiv.md](structure/services/service-osiv.md)                   | When OSIV is disabled, load all data the view needs inside the transaction boundary so lazy associations never reach the view layer and produce `LazyInitializationException`                           |
